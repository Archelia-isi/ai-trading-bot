# SPECIFICA DI PROGETTO: AI Quantitative Trading Bot (Web UI & Alarms)

## 1. Visione del Progetto
Sviluppare un sistema di trading automatizzato in Python, accessibile tramite Dashboard Web interattiva da browser, che esegue operazioni speculative rapide (scalping/day trading) tramite API di Capital.com. Le decisioni operative sono guidate dall'analisi del sentiment in tempo reale eseguita dalle API di Google Gemini su notizie e forum. Il sistema deve notificare l'utente in tempo reale sul proprio smartphone.

## 2. Regola d'Oro: Localizzazione (Italiano)
Il progetto è destinato a utenti italiani. L'agente DEVE rispettare queste regole di localizzazione:
* **Interfaccia (UI):** Tutti i testi, i titoli, i grafici e i pulsanti su Streamlit devono essere in italiano (es. "Saldo", "Posizioni Aperte", "Profilo di Rischio").
* **Notifiche:** I messaggi Telegram/WhatsApp devono essere inviati in italiano.
* **Prompt AI:** Il prompt inviato a Gemini API DEVE contenere l'istruzione esplicita: *"Rispondi sempre e solo in lingua italiana, mantenendo la struttura JSON richiesta"*.
* **Log:** I log a schermo e nel database devono essere comprensibili in italiano.

## 3. Stack Tecnologico ed Infrastruttura
L'agente deve configurare il progetto rispettando rigorosamente questo stack:
* **Core:** Python 3.11+ (Gestione asincrona con `asyncio`).
* **Interfaccia UI (Browser):** Streamlit.
* **Database & Stato:** Neon DB (PostgreSQL Serverless).
* **Hosting / Runtime:** Railway (connesso al repository GitHub per CI/CD automatico).
* **Notifiche Esterne:** API di Telegram o API di Twilio (WhatsApp). Le chiavi andranno nel file `.env`.

## 4. Architettura Logica a 6 Livelli

| Modulo | Responsabilità | Dettaglio Tecnico |
| :--- | :--- | :--- |
| **1. Web Dashboard (UI)** | Interfaccia utente via browser. | Streamlit UI: Pulsanti Avvia/Ferma, Selettore Profilo, Grafico Profitti, Log in tempo reale. |
| **2. Data Ingestion** | Raccogliere dati live (prezzi, notizie). | Background task asincrono per i WebSocket di Capital.com e API notizie. |
| **3. Sentiment Engine** | Fornire uno score (1-100) e motivazione. | Chiamate a Gemini API protette da try/except per timeout. |
| **4. Quant Engine & Orders**| Incrociare score/rischio e inviare ordini. | Logica matematica (size, entry, SL/TP) e chiamate API REST a Capital.com. |
| **5. Notification Engine** | Inviare messaggi push all'utente. | Trigger di messaggi HTTP verso Telegram/WhatsApp al verificarsi di eventi chiave. |
| **6. State & Logger** | Registrare ogni decisione. | Scrittura su Neon DB (tabella `trade_logs`). |

## 6. Requisiti di Sicurezza (Failsafe) e Logica di Allarme
Il sistema deve attenersi a queste regole e inviare istantaneamente un **messaggio Telegram/WhatsApp (in italiano)** in questi casi:
* **Esecuzione Trade:** *"✅ Operazione Chiusa [Asset]. Profilo: [Nome]. Profitto/Perdita: [Cifra] €"*.
* **Kill-Switch Manuale:** Se premuto dall'utente via Web UI, chiudere tutto e inviare: *"⚠️ KILL SWITCH ATTIVATO MANUALMENTE. Tutte le posizioni chiuse."*
* **Kill-Switch Automatico (Drawdown):** *"🚨 ALLARME CRITICO: Drawdown superato. Bot arrestato per sicurezza."*
* **Timeout / Disconnessione:** Se Capital.com o Gemini non rispondono, inviare alert di disconnessione.
